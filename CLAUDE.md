# Assignr Helper

Referee app: open and assigned games across several assignors, a "games available" email with a live quick link, and fast post-game score and card entry. Assignr is the first integration; all vendor code sits behind `ISchedulingProvider` (`functions/src/integrations/ports/`). The global `~/.claude/CLAUDE.md` standards apply; this file records project facts and where reality differs from them.

## Architecture

- Angular 22.2 SPA (zoneless, OnPush, signals) in `src/`. It talks only to our `/api/**`; it never calls a vendor.
- One Express app served by the HTTPS function `assignr_helper_api` (`functions/src/index.ts`, `us-east4`, 512MiB).
- Canonical data lives in Spanner database `assignr-helper` on the shared instance `shared` in project `hamble-creek-holdings`. The app runs in GCP project `assignr-helper-prod`.
- Reads come from our copy. Writes (accept, decline, claim) go through a service that calls the provider, then updates our copy and the audit trail.
- Sync (`functions/src/sync/`): `run_sync` pulls one kind (reference data, open games, my games) through `ISchedulingProvider`, merges with `merge_stored_game`, and records an `ISyncRun`. `sync_connection` runs the three in order. Stores are ports (`IGameStore`, `IVenueStore`, `IOrganizationStore`, `ISyncRunStore`) with in-memory and Spanner implementations (`functions/src/sync/stores/`). Both run the same contract tests (`contracts/`); the Spanner suite runs only when `SPANNER_EMULATOR_HOST` is set (CI does it after provisioning the emulator). The Spanner stores use the Spanner client directly rather than core-server's CRUD helpers on purpose: sync rows arrive already stamped by `merge_stored_game`, and per-row audit logging of bulk system sync would be noise. Removal is safe by design: a game is only marked gone when its organization was read completely (`IListGamesResult.complete_organization_external_ids`), the open list owns `is_open`, the account's own list owns `is_mine`, and games are soft-removed (`removed_at`), never deleted. It is exposed and scheduled: `ConnectionSyncService` (`sync/connection_sync.service.ts`) syncs one connection on demand or all eligible ones on a schedule, then records the result on the connection (`derive_connection_outcome`: clean success stamps `last_sync_at`; rejected or missing credentials flag it NEEDS_ATTENTION so it is never synced automatically again; other failures only record the error). Routes (all tenant-scoped, after the auth middleware): `GET /api/connections` (games.read), `POST /api/connections/:connection_id/sync` (sync.run; body `{ refresh_reference_data? }`; 404 other tenant's or missing, 409 not CONNECTED), `GET /api/connections/:connection_id/sync-runs?limit=` (games.read). A platform administrator needs `X-Acting-Tenant-Id` for these (otherwise 400 TENANT_REQUIRED). `sync_connections_job` (`index.ts`) runs every 15 minutes, 540 s timeout, least recently synced first, stopping to start new connections after 7 minutes, never retrying the whole job. **Provider credentials are per tenant** (see the next bullet group, "Connections and credentials"): sessions get tokens from `ClientCredentialsTokenSource`, which reads the tenant's own client id and secret from the vault. The sync runs inside the HTTP request, so a very large first sync can take minutes; move it behind the outbox if that becomes a problem. `npm --prefix functions run typecheck` also typechecks specs (`tsconfig.spec.json`); contract and fixture files are excluded from the build output.

## Deviations from the global standards (follow the libraries' reality)

- `@hch-shared-libraries/ui-kit` has an empty root export. Import from subpaths (`/app`, `/core`, `/data`, `/common`, `/authorization`).
- `TranslationService` is app-owned and bound to the ui-kit `TRANSLATION_PROVIDER` token.
- `hchUserDate` is `UserDatePipe` from `ui-kit/core`. It has no per-call time zone yet (issue #996), so venue-local time rendering is blocked on it.
- core-server has no shared Firebase auth middleware (#987), Swagger helper (#989) or connector framework (#986). The auth middleware is app-owned in `functions/src/auth/` until #987 ships (see below); it composes core-server's role switcher, tenant impersonator and permission service.
- The generated Angular app uses Vitest through `ng test`; `ng generate` is configured for `.component.ts` file names (2016 style guide).

## Blocked work (do not stub)

- **Shared packages are installed (14.17.0), but only the shell is wired.** Not yet built on top of them: Spanner stores, `hch-schema` tables (tenants, audit_log, outbox, communications, share links), the auth middleware, and scheduling. If installs return 403, the registry token expired (about an hour); rerun `npx google-artifactregistry-auth`. `functions/` needs its own `.npmrc` for the scope, and its vitest stays on ^4 because core-server's optional peer rejects vitest 5.
- **Shell wiring (`src/app/core`).** `AppComponent` renders `hch-app-shell`; `IdentityService` implements the header's identity contract over an `IAuthGateway` port (Firebase Auth loaded lazily; the Auth emulator in development via `src/environments/environment.ts`). `AppTranslationService` layers `assets/i18n/<locale>.json` over the ui-kit's bundled strings. Every nav entry has a guarded route that renders `FeaturePlaceholderComponent` until the real feature exists. `/connections` is real: `src/app/features/connections/` (list, add, replace credentials, test, disconnect, sync, sync history) over `ConnectionsApiService`, with `SessionService` (`src/app/core/services/session/`, `GET /api/me`) gating actions by permission. The client secret is entered through `hch-secret-entry-form` (replace) or a masked input (add) and exists only as the value of that one request; it is never kept in a signal, toast or log. Known limits of the ui-kit form: it has no error slot and saves one field per submit, so after a failed replace the secret must be retyped. The page's E2E (`e2e/connections_page.spec.ts`) mocks `/api/**` with `page.route`. Sign-in must also be enabled in the Firebase console for `assignr-helper-prod` (email/password and Google); that cannot be scripted from here.
- **Local emulators.** Auth: `npm run emulators` (Auth emulator on 9099, UI disabled because 4000 is commonly taken), then `npm run seed:auth` (idempotent, refuses non-local hosts). The seeded test user lives in `scripts/seed/auth_users.seed.json` (emulator-only credentials). Playwright starts or reuses the Auth emulator and seeds it in `e2e/global_setup.ts`; the emulator port is shared by concurrent runs, which only read the seeded user. Spanner: a shared emulator may already be running on `localhost:9010` (REST 9020); use only this app's own ids with `SPANNER_EMULATOR_HOST=localhost:9010 npm run spanner:provision` (project `assignr-helper-local`, instance `local`, database `assignr-helper`), then `SPANNER_PROJECT_ID=assignr-helper-local SPANNER_INSTANCE_ID=local SPANNER_DATABASE_ID=assignr-helper npm --prefix functions run migrate` after `npm run functions:build`. Never touch other apps' databases on the shared emulator. Integration tests that need an emulator are skipped unless its env var is set: `SPANNER_EMULATOR_HOST` (store and resolver contracts) and `FIREBASE_AUTH_EMULATOR_HOST` (real-token auth tests, `src/auth/auth_emulator.integration.spec.ts`; CI runs it with `firebase emulators:exec`).
- **Connections and credentials (`functions/src/connections/`).** Each tenant enters its own Assignr client id and secret (nothing is stored platform-wide). They live only in Secret Manager (`SecretManagerCredentialVault`, secret `tenant-<tenant_id>-connection-<connection_id>`, JSON) behind the `ICredentialVault` port; the connection row keeps only a reference, status and label. `ClientCredentialsTokenSource` exchanges them for short-lived tokens (cached in memory with a 120 s skew, single-flight per connection) and is invalidated whenever credentials change. `ConnectionAdminService` (routes in `connections_admin.routes.ts`, all `CONNECTIONS_MANAGE`, tenant required): `POST /api/connections` (verifies the credentials with the provider via `GET /current_account` before anything is stored; reconnecting an account the tenant already has reuses its connection), `PUT /api/connections/:id/credentials` (rotate; omit `client_id` to keep the stored one; the new credentials must belong to the same account, else 409 ACCOUNT_MISMATCH), `POST /api/connections/:id/test` (read-only; `{ok, failure}`), `POST /api/connections/:id/disconnect` (deletes the secret, marks DISCONNECTED, keeps synced games). Errors: 422 CREDENTIALS_REJECTED, 502 PROVIDER_UNAVAILABLE, 404 for another tenant's connection. Every change writes an `audit_log` row (migration 0004, core-server `audit` subpath) with an allow-listed before/after (id, provider, status, label, external account id), the actual and effective role, never a secret. Credentials are accepted in request bodies only and are never returned, logged or put in an error. `SECRET_MANAGER_PROJECT_ID` is a required env var (fail-closed). The auth-code OAuth flow for individual referees is still future work; client credentials act as the tenant's own Assignr account.
- **Games list (`functions/src/games/`).** `GET /api/games` (games.read, tenant-scoped, platform admins need `X-Acting-Tenant-Id`) reads our stored copy across all of the tenant's connections and returns `{ data: { locations: [{ location_label, dates: [{ local_date, games: IGameView[] }] }], total, truncated } }`, grouped by location (A-Z, unknown last), then date, then start time; at most 2000 games (`truncated` when more match). Query (strict, unknown params are 400): `scope` OPEN (default) | MINE | ALL, `from`/`to` UTC ms (default now-3h to now+120d, max 400 days), `search` (<=100 chars; teams, league, level, age group, venue, location group, organization), `connection_id`, `organization_id`, `league`, `level`, `age_group`, `location_group`, `only_with_open_slots`, `include_cancelled`. Removed games are never returned; fees are always null until the Assignr fee shape is verified. Backed by `list_games` / `list_venues` / `list_all_organizations` on the store ports (in-memory and Spanner, same contract tests). The Angular screen is `src/app/features/games/` (route `games`, read-only): scope tabs (a select on phones), debounced search, facet selects and toggles in an expansion panel on phones, sticky location headers, and states for no access, errors, empty and truncated. Facet option lists come from a second request that omits the facet selections, so picking one never hides the alternatives. Times use `hchUserDate` in the user's zone until #996 adds a per-call time zone. A live Assignr account sends venue latitude/longitude as strings; the schema accepts both.
- **Quick links (`functions/src/quick_links/`).** Owner routes (`quick_links.manage`, tenant-scoped, platform admins need `X-Acting-Tenant-Id`): `POST /api/quick_links` (optional `scope { organization_ids, levels, date_start, date_end }` with UTC-midnight dates, optional `expires_at`; absent means never expires; returns the token ONCE with `path: /q/<token>`), `GET /api/quick_links`, `POST /api/quick_links/:link_id/revoke` (idempotent). Only the SHA-256 of the token is stored; list, revoke, audit rows and logs never contain it. Create and revoke write `quick_link` audit rows. Public route (no sign-in, mounted before auth): `GET /api/public/q/:token/games?search&level&league&location_group` returns open, unfilled, not-cancelled, future games inside the link's scope as `IPublicGame` only (no organization names, assignees, fees, provider ids), grouped location > date > time, capped at 1000, plus facet option arrays; unknown, malformed, revoked and expired tokens all return the byte-identical `404 {code, message}`. Every public response sets `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, `X-Robots-Tag: noindex, nofollow` and `X-Content-Type-Options: nosniff`. Rate limits (in memory, per function instance, upstream #794): 60 requests/min per IP and 20 failed lookups/min per IP (429 with `Retry-After`). The client IP comes from `trust proxy` set by env `TRUSTED_PROXY_HOPS` (optional, default 2 for Hosting then the Google front end; invalid values refuse to start). **Verify the hop count after the first deploy:** too low and every visitor shares one bucket, too high and a direct caller of the function URL can choose its address. Public data is read from our synced copy, so it is as fresh as the last sync (15 minutes); the debounced provider refresh from the plan is not built. Every successful public request counts as a view, so filtered searches inflate `view_count`. `IQuickLinkStore` has in-memory and Spanner implementations sharing a contract suite. The Angular side: the owner screen is `src/app/features/quick_links/` (route `quick-links`; create dialog with optional levels, date window and expiry presets defaulting to 30 days, the link URL shown once with Copy and never stored or logged, revoke with confirmation; there is no rotate, create a new link then revoke the old one). The public page is `src/app/features/public_quick_link/` at `/q/:token`: outside the shell chrome, no auth guard, `noindex` meta, search and facet filters, auto-refresh every 60 s only while the tab is visible, and one calm message for any unusable link. `app_bearer_auth_interceptor` wraps the ui-kit interceptor and never attaches the Firebase token to `/api/public/`; the public service turns every HTTP error into a token-free `PublicQuickLinkError` before logging.
- **Auth (`functions/src/auth/`).** `create_auth_middleware` verifies the bearer ID token (`FirebaseTokenVerifier`, revocation checked), resolves the caller's tenant and role (`IMembershipResolver`, Spanner `tenants` and `tenant_members`, migration 0003; platform admins belong to the single PLATFORM tenant), then applies `X-Acting-Tenant-Id` (platform administrators only) and `X-Effective-Role` (assumable lower roles only; anything else is 403), and sets `req.auth = { real, effective }`. Authorization checks the effective role through `require_app_permission(PermissionKey.X, service)`; roles and their permissions are fixed in code (`StaticRoleStore`, `role_definitions.constant.ts`). Order in `create_app`: public routers, auth middleware, protected routers; with no `auth` configured nothing protected is served. `GET /api/me` returns the effective and real context. `create_production_app` reads `SPANNER_*` from `functions/.env.<project>` and throws at start-up when any is missing. Not built yet: onboarding (nothing creates a tenant or membership, so a brand-new user gets 403 NO_MEMBERSHIP until one is inserted), audit rows for acting-as, and an invitation flow.
- **Local tests:** `npm test` can fail to start worker processes on a loaded Windows machine (`spawn UNKNOWN`); `VITEST_MAX_WORKERS=2 npm test` avoids it.

Reports are captured locally; `ProviderCapability.MATCH_REPORT_SUBMIT` is intentionally absent for Assignr.

## Conventions worth repeating

- snake_case for variables, methods, properties and files; PascalCase classes; `I`-prefixed interfaces; UPPER_SNAKE enum members. One entity per file. Enums, never string unions.
- Dates are UTC milliseconds. Calendar dates (e.g. `games.local_date`) are UTC-midnight milliseconds, rendered with `UserDateFormat.CALENDAR_DATE`.
- Every tenant-owned row has `tenant_id` and every query filters on it. Audit columns on every table. Secrets only in Secret Manager.
- A `catch` that sets a generic message must also `console.error` the real error.
