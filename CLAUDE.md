# Assignr Helper

Referee app: open and assigned games across several assignors, a "games available" email with a live quick link, and fast post-game score and card entry. Assignr is the first integration; all vendor code sits behind `ISchedulingProvider` (`functions/src/integrations/ports/`). The global `~/.claude/CLAUDE.md` standards apply; this file records project facts and where reality differs from them.

## Architecture

- Angular 22.2 SPA (zoneless, OnPush, signals) in `src/`. It talks only to our `/api/**`; it never calls a vendor.
- One Express app served by the HTTPS function `assignr_helper_api` (`functions/src/index.ts`, `us-east4`, 512MiB).
- Canonical data lives in Spanner database `assignr-helper` on the shared instance `shared` in project `hamble-creek-holdings`. The app runs in GCP project `assignr-helper-prod`.
- Reads come from our copy. Writes (accept, decline, claim) go through a service that calls the provider, then updates our copy and the audit trail.
- Sync (`functions/src/sync/`): `run_sync` pulls one kind (reference data, open games, my games) through `ISchedulingProvider`, merges with `merge_stored_game`, and records an `ISyncRun`. `sync_connection` runs the three in order. Stores are ports (`IGameStore`, `IVenueStore`, `IOrganizationStore`, `ISyncRunStore`) with in-memory and Spanner implementations (`functions/src/sync/stores/`). Both run the same contract tests (`contracts/`); the Spanner suite runs only when `SPANNER_EMULATOR_HOST` is set (CI does it after provisioning the emulator). The Spanner stores use the Spanner client directly rather than core-server's CRUD helpers on purpose: sync rows arrive already stamped by `merge_stored_game`, and per-row audit logging of bulk system sync would be noise. Removal is safe by design: a game is only marked gone when its organization was read completely (`IListGamesResult.complete_organization_external_ids`), the open list owns `is_open`, the account's own list owns `is_mine`, and games are soft-removed (`removed_at`), never deleted. It is exposed and scheduled: `ConnectionSyncService` (`sync/connection_sync.service.ts`) syncs one connection on demand or all eligible ones on a schedule, then records the result on the connection (`derive_connection_outcome`: clean success stamps `last_sync_at`; rejected or missing credentials flag it NEEDS_ATTENTION so it is never synced automatically again; other failures only record the error). Routes (all tenant-scoped, after the auth middleware): `GET /api/connections` (games.read), `POST /api/connections/:connection_id/sync` (sync.run; body `{ refresh_reference_data? }`; 404 other tenant's or missing, 409 not CONNECTED), `GET /api/connections/:connection_id/sync-runs?limit=` (games.read). A platform administrator needs `X-Acting-Tenant-Id` for these (otherwise 400 TENANT_REQUIRED). `sync_connections_job` (`index.ts`) runs every 4 hours, 540 s timeout, least recently synced first, stopping to start new connections after 7 minutes, never retrying the whole job. **Provider credentials are per tenant** (see the next bullet group, "Connections and credentials"): sessions get tokens from `ClientCredentialsTokenSource`, which reads the tenant's own client id and secret from the vault. The sync runs inside the HTTP request, so a very large first sync can take minutes; move it behind the outbox if that becomes a problem. `npm --prefix functions run typecheck` also typechecks specs (`tsconfig.spec.json`); contract and fixture files are excluded from the build output.

## Deviations from the global standards (follow the libraries' reality)

- `@hch-shared-libraries/ui-kit` has an empty root export. Import from subpaths (`/app`, `/core`, `/data`, `/common`, `/authorization`).
- `TranslationService` is app-owned and bound to the ui-kit `TRANSLATION_PROVIDER` token.
- `hchUserDate` is `UserDatePipe` from `ui-kit/core`. Since 14.31.0 it takes a per-call IANA time zone (`{{ ms | hchUserDate:'time-only-with-zone':zone }}`) and has `WEEKDAY_DATE` and `SHORT_OMIT_CURRENT_YEAR` formats (#996, #1025 closed). The app uses them: every game carries `time_zone` (its own `game_time_zone`, else its venue's, else null; names that are not real IANA zones are dropped), the games rows and the public page show kick-off on the venue clock with its zone (`TIME_ONLY_WITH_ZONE`, e.g. "9:00 AM CDT", falling back to the viewer's zone when unknown), and date headings are `WEEKDAY_DATE` formatted in `UTC` because `local_date` is a calendar date stored as UTC midnight ("Saturday, Oct 10", no year). Emails render each game on its own venue clock, falling back to the digest zone.
- core-server now ships a Firebase auth module, Swagger helper, connector framework and share-link module (#986 to #990 closed, installed 14.31.0), but the app still uses its own: the auth middleware in `functions/src/auth/` (see below), the sync engine in `functions/src/sync/` and the quick links in `functions/src/quick_links/`. Moving to the library versions is a separate, deliberate change; it composes core-server's role switcher, tenant impersonator and permission service.
- The generated Angular app uses Vitest through `ng test`; `ng generate` is configured for `.component.ts` file names (2016 style guide).

- **Connections and credentials (`functions/src/connections/`).** Each tenant enters its own Assignr client id and secret (nothing is stored platform-wide). They live only in Secret Manager (`SecretManagerCredentialVault`, secret `tenant-<tenant_id>-connection-<connection_id>`, JSON) behind the `ICredentialVault` port; the connection row keeps only a reference, status and label. `ClientCredentialsTokenSource` exchanges them for short-lived tokens (cached in memory with a 120 s skew, single-flight per connection) and is invalidated whenever credentials change. `ConnectionAdminService` (routes in `connections_admin.routes.ts`, all `CONNECTIONS_MANAGE`, tenant required): `POST /api/connections` (verifies the credentials with the provider via `GET /current_account` before anything is stored; reconnecting an account the tenant already has reuses its connection), `PUT /api/connections/:id/credentials` (rotate; omit `client_id` to keep the stored one; the new credentials must belong to the same account, else 409 ACCOUNT_MISMATCH), `POST /api/connections/:id/test` (read-only; `{ok, failure}`), `POST /api/connections/:id/disconnect` (deletes the secret, marks DISCONNECTED, keeps synced games). Errors: 422 CREDENTIALS_REJECTED, 502 PROVIDER_UNAVAILABLE, 404 for another tenant's connection. Every change writes an `audit_log` row (migration 0004, core-server `audit` subpath) with an allow-listed before/after (id, provider, status, label, external account id), the actual and effective role, never a secret. Credentials are accepted in request bodies only and are never returned, logged or put in an error. `SECRET_MANAGER_PROJECT_ID` is a required env var (fail-closed). The auth-code OAuth flow for individual referees is still future work; client credentials act as the tenant's own Assignr account.
- **Games list (`functions/src/games/`).** `GET /api/games` (games.read, tenant-scoped, platform admins need `X-Acting-Tenant-Id`) reads our stored copy across all of the tenant's connections and returns `{ data: { locations: [{ location_label, dates: [{ local_date, games: IGameView[] }] }], total, truncated } }`, grouped by location (A-Z, unknown last), then date, then start time; at most 2000 games (`truncated` when more match). Query (strict, unknown params are 400): `scope` OPEN (default) | MINE | ALL, `from`/`to` UTC ms (default now-3h to now+120d, max 400 days), `search` (<=100 chars; teams, league, level, age group, venue, location group, organization), `connection_id`, `organization_id`, `league`, `level`, `age_group`, `location_group`, `only_with_open_slots`, `include_cancelled`. Each game carries `time_zone` (IANA zone or null) and `slots` (every position in game order as `{ position, state: OPEN|FILLED|MINE }`, using the provider's position names such as Referee, Asst. Referee or Mentor, never who holds it) and `open_positions` (names of the open ones). The screen lists open positions first as "Referee: Open" chips. Removed games are never returned; fees are always null until the Assignr fee shape is verified. Backed by `list_games` / `list_venues` / `list_all_organizations` on the store ports (in-memory and Spanner, same contract tests). The Angular screen is `src/app/features/games/` (route `games`, read-only; the games are one ui-kit `hch-grouped-agenda-list` with levels location then date, or date alone, rows non-interactive, the kick-off in the list's own time column, collapsed groups kept in a page signal only): scope tabs (a select on phones), debounced search, facet selects and toggles in an expansion panel on phones, sticky location headers, and states for no access, errors, empty and truncated. A "Group by venue" switch (default on, remembered per browser in localStorage) turns the venue cards into one "Games by date" card ordered by date then start time, with each row naming its own location; it only rearranges the loaded result (`flatten_games_by_date`), so it makes no request. Facet option lists come from a second request that omits the facet selections, so picking one never hides the alternatives. Kick-off times and date headings follow the venue-local rules in the `hchUserDate` bullet above. A live Assignr account sends venue latitude/longitude as strings; the schema accepts both.
- **Quick links (`functions/src/quick_links/`).** Owner routes (`quick_links.manage`, tenant-scoped, platform admins need `X-Acting-Tenant-Id`): `POST /api/quick_links` (optional `scope { organization_ids, levels, date_start, date_end }` with UTC-midnight dates, optional `expires_at`; absent means never expires; returns the token ONCE with `path: /q/<token>`), `GET /api/quick_links`, `POST /api/quick_links/:link_id/revoke` (idempotent). Only the SHA-256 of the token is stored; list, revoke, audit rows and logs never contain it. Create and revoke write `quick_link` audit rows. Public route (no sign-in, mounted before auth): `GET /api/public/q/:token/games?search&level&league&location_group` returns open, unfilled, not-cancelled, future games inside the link's scope as `IPublicGame` only (no organization names, assignees, fees, provider ids; each game lists its positions as `slots: { position, is_open }[]`, names only, and a `time_zone` so the page can show the venue clock), grouped location > date > time, capped at 1000, plus facet option arrays; unknown, malformed, revoked and expired tokens all return the byte-identical `404 {code, message}`. Every public response sets `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, `X-Robots-Tag: noindex, nofollow` and `X-Content-Type-Options: nosniff`. Rate limits (in memory, per function instance, upstream #794): 60 requests/min per IP and 20 failed lookups/min per IP (429 with `Retry-After`). The client IP comes from `trust proxy` set by env `TRUSTED_PROXY_HOPS` (optional, default 2 for Hosting then the Google front end; invalid values refuse to start). **Verify the hop count after the first deploy:** too low and every visitor shares one bucket, too high and a direct caller of the function URL can choose its address. Public data is read from our synced copy, so it is as fresh as the last sync (4 hours); the debounced provider refresh from the plan is not built. Every successful public request counts as a view, so filtered searches inflate `view_count`. `IQuickLinkStore` has in-memory and Spanner implementations sharing a contract suite. The Angular side: the owner screen is `src/app/features/quick_links/` (route `quick-links`; create dialog with optional levels, date window and expiry presets defaulting to 30 days, the link URL shown once with Copy and never stored or logged, revoke with confirmation; there is no rotate, create a new link then revoke the old one). The public page is `src/app/features/public_quick_link/` at `/q/:token` (the same `hch-grouped-agenda-list`, levels location then date): outside the shell chrome, no auth guard, `noindex` meta, search and facet filters, auto-refresh every 60 s only while the tab is visible, and one calm message for any unusable link. `app_bearer_auth_interceptor` wraps the ui-kit interceptor and never attaches the Firebase token to `/api/public/`; the public service turns every HTTP error into a token-free `PublicQuickLinkError` before logging.
- **Email (`functions/src/{contacts,email_settings,email_delivery,email_drafts,unsubscribe}/`).** Owner routes (all `EMAIL_SEND`, tenant-scoped): `/api/email/settings` (the tenant's own SendGrid key and sender details live only in Secret Manager as `tenant-<id>-sendgrid`; the key is never returned, logged or audited), `/api/contacts` (consent must be attested; an unsubscribed address can never be re-added; deletion keeps a hashed suppression record in `email_suppressions`), `/api/email_drafts` (CRUD, `preview`, `test_send`, `send`). The email is rendered from live data at preview and send time, and each game's line names the open positions ("2 open positions: Referee, Asst. Referee ×2"). Send is enforced server-side: email configured, only consented contacts (re-checked per recipient), the confirmed count must equal the recomputed count, at most 100 recipients, no empty digest, and an atomic DRAFT/PARTIALLY_SENT to SENDING lock with stale-lock takeover after 10 minutes. Results are stored per contact (ids and safe error codes only) in `email_draft_recipients`, so a retry only emails recipients without a delivered email. The quick link is minted at send time (token never stored); the draft's `updated_at` is its optimistic-concurrency version. Public unsubscribe is `GET`/`POST /api/public/unsubscribe/:token` (stateless HMAC token; signing key is platform secret `assignr-helper-unsubscribe-key-v1`, auto-created on first use; GET has no side effects; uniform 404; same hardening as quick links). `PUBLIC_APP_ORIGIN` is a required env var (https origin; `http://localhost` only under the emulators). - **Match reports (`functions/src/match_reports/`, `src/app/features/match_reports/`).** API (reads `games.read`, writes `reports.write`, tenant-scoped): `POST /api/match_reports {game_id}` (creates the DRAFT for one of the tenant's own, non-cancelled games, 201, or returns the existing one, 200), `GET /api/match_reports?status&game_id` (summaries, newest first, cap 200), `GET /api/match_reports/:id`, `PUT .../scores` (0-99 or null, `client_revision`), `POST .../incidents` (idempotency key, `team_side` HOME|AWAY required, type, jersey 0-99, minute 0-130, reason), `DELETE .../incidents/:incident_id`, `POST .../ready` (422 `REPORT_NOT_READY` with a violation per blocker) and `.../reopen`. Rules: scores are last-writer-wins by `client_revision` (a lower revision is ignored and the stored report returned); incident requests do NOT move `client_revision`; every write is a compare-and-swap on `lock_version` with at most 5 attempts (409 `REPORT_CONFLICT` after that); the idempotency key is unique tenant-wide (reuse on another report is 409 `IDEMPOTENCY_KEY_CONFLICT`); at most 60 incidents (409 `TOO_MANY_INCIDENTS`); only ready and reopen write audit rows (never notes); `yellow_count` in summaries includes second yellows and `red_count` is straight reds only. Report notes are classified PII and `jersey_number` CONFIDENTIAL. Known limit: incident ids are server-generated and the idempotency key lives only on the incident row, so a delayed replay of an add that was already undone would re-create it (a fix needs a tombstone table, migration 0006); the client queue guards against it. The screens: list `match-reports` (my games from the last 7 days, "Needs a report" and "Reported", one giant "Report this game" button) and entry `match-reports/:game_id` (one page: score steppers, card panel with team and card tiles, number pad, minute chips and reasons, Undo toast, finish summary, Mark ready). Autosave is `MatchReportSyncService`: edits apply locally at once and go through a durable `localStorage` queue per report (sequential flush, score edits merged, capped backoff, flush on the `online` event, an unacknowledged add and its undo cancel each other); Mark ready is disabled while anything is waiting. The entry screen needs a connection to OPEN (it creates or fetches the report first); after that losing signal is tolerated. Leaving with unsent edits keeps them on the device and sends them the next time that report is opened. Not built: submitting to Assignr (blocked), editing notes or OTHER incidents, a service worker for offline opening. The Spanner suite for the match report store has never run (no emulator); run it before first production use.

## Conventions worth repeating

- snake_case for variables, methods, properties and files; PascalCase classes; `I`-prefixed interfaces; UPPER_SNAKE enum members. One entity per file. Enums, never string unions.
- Dates are UTC milliseconds. Calendar dates (e.g. `games.local_date`) are UTC-midnight milliseconds, rendered with `UserDateFormat.CALENDAR_DATE`.
- Every tenant-owned row has `tenant_id` and every query filters on it. Audit columns on every table. Secrets only in Secret Manager.
- A `catch` that sets a generic message must also `console.error` the real error.
